# 验收方式与状态边界

本工程实现 39 个双语页面，`stage=ready` 表示工具链、操作、服务、页面和修改合同齐备。`ready`、格式有效、应用检查通过、素材授权与部署是不同状态，不能相互替代。

本文件列出验收方法和已知限制，不独立宣称全部通过。最终执行时间、退出码、环境、服务关闭、源码摘要和未执行项由 `.tpl/reports/verification.json` 如实记录；缺失或摘要过期时不能引用为当前源码证明。

## 自动检查合同

在本地 WSL Linux 文件系统冻结安装后执行：

| 项目 | 命令 | 目的 |
| --- | --- | --- |
| 类型 | `pnpm run typecheck` | strict TypeScript 与页面属性 |
| 静态检查 | `pnpm run lint` | 应用源码 ESLint |
| 合同测试 | `pnpm run test` | 页面双语路径、环境与许可约束 |
| 构建 | `pnpm run build` | 独立应用生产编译 |
| 协议 | `pnpm tpl:check` | 资料引用、工具链、Git 索引和报告一致性 |

项目操作的 cwd/argv、副作用与超时见 `project.json`。`bundle` 要求干净的已提交源码，只在本地 WSL Linux 文件系统打包；打包不表示已部署。协议检查不重新执行应用，不证明权利来源。

## 真实页面、交互与动效

启动 `pnpm start`，默认 http://127.0.0.1:43652 ，以 `/` 返回 200 为就绪信号；实际端口可由进程环境调整。完成验收后停止本次服务，在报告中记录停止结果。

1. 逐页访问两种语言，检查主标题、站内导航、未知路径、页面切换、查询和锚点保持。
2. PC 1440×1000、iPad 834×1180、H5 390×844，补测 320px 窄屏。记录视口、内容宽度、实际图片像素、溢出、裁切与按钮操作。
3. 检查菜单展开、分类筛选、加载更多、详情相关链接、文章目录、FAQ、服务切换和表单。表单应明确提示尚未发送或保存，不能把本地成功当成真实业务成功。
4. 按根 `docs/MOTION.md` 在三端触发文字、图片、轮播、循环、菜单与视频。比较初始/运行/结束；循环须检查暂停/恢复，视频须检查播放时间推进。静态截图或路由 200 不构成动效通过。
5. 实际滚动长页、明暗区块、菜单内部、横向图库和方案对比。检查主题、键盘、触控、背景锁定恢复、滚动条占宽与离开模板后样式清理。
6. 检查浏览器控制台、网络失败、图片/字体/视频加载及系统减少动态设置。自动播放被限制时应通过用户控件测试实际播放。

## 已知限制

- 尚无全部 39 页原站动效的逐帧时长、曲线与轨迹量化证据，不声明完整 1:1。
- 部分效果只有参考结构线索，未经逐项动态对照时仍记为未验证；详见 `docs/MOTION.md`。
- 原站详情复用错误标题和主体；本实现按 slug 校正并提供独有双语演示内容。除保留部分对应主题外，正文不是原站逐字复刻。
- 客户、地址、报价、统计等属于演示；无真实后台、持久化、支付、预约或邮件发送。
- 参考照片、视频、图形和原站内容的商业再分发许可尚未确认，保持未上架和不可再分发声明。
- 系统原生滚动条、触控惯性、视频解码与自动播放策略存在设备差异，不能仅凭 CSS 声明确认所有设备一致。
